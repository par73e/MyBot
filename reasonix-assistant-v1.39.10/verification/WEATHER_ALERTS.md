# 上海官方天气预警模块

运行版本：`v1.39.10-assistant.38-weather-alert-cadence`，2026-10-26北京时间16:29部署启用；初始模块16:17上线，随后修正启动时的时间格对齐。生产状态与原生自动检查证据见`weather-alert-deployment.json`，Linux验收见`weather-alert-linux-acceptance.json`。本次Sir已授权完善并部署；原有晨报、邮件、PR及个人作息保留。

## 行为与范围

- 上海全市、中心城区和各区，支持台风、暴雨、暴雪、寒潮、大风、低温、霜冻、高温、雷电、冰雹、大雾、霾、道路结冰及来源明确标记的雷雨大风，蓝/黄/橙/红均可通知。中心城区与全市分别建状态；不冒充GPS或精确街道覆盖。
- 统一Heartbeat新增`weather_alerts`触发器、`weather_alert_check`原生模块，作息内每5分钟一次。成功后的下次检查对齐作息触发器的5分钟时间格，服务在时间格中途启动也不会跳过下一格；使用已有独立weather_check工作通道；单轮40秒，其中源采集预算30秒，HTTP单次8秒，三个固定源独立有界并发，不调用模型或和风接口。
- 三源为中央气象台上海JSON查询、中国天气网上海JSONP和中国天气网全国列表/详情。任一可信源取得有效新预警、升级或后续发布即独立提交并入通知队列，不等待其余来源完成/赞同。整轮遇错也不能撤销已提交的有效观察。
- 第一次接入会报告当前有效的新预警；明确过期的历史项不会报告。身份以规范区域+灾种组合、官方发布时间与级别核对。落后的时间不覆盖较新记录，同一时间低等级不覆盖高等级；跨源同一发布去重。等级升高及较新发布能够形成新事件，发送前淘汰被新状态取代的旧队列项。
- 空列表、超时、HTML验证页、格式变化和部分读取失败都不表示“解除”。只有可信固定源上的明确解除声明/Cancel消息能够结束对应已知预警。有效截止仅标记过期，不自动宣称官方解除。解除后同时间或较旧的正向记录不能重新激活。
- 正常通知是程序生成的中文事实、原文有限摘录、来源及官方链接，保留发布日期和已提供的截止时间。没有正文时明确说详情未取得；没有截止时间就不编造。内容始终为外部数据，不能触发执行指令、回复、修改记忆或其他个人状态。
- 调度、取数、提交和发送都检查最新作息、日期覆盖、触发器与模块开关，配置revision变化后旧采集不提交；没有夜间例外。作息外事件不自动顺延重放，后续窗口只依据重新观察仍相关的状态。发送还检查记录最近10分钟内重新观察、未过期且事件仍为最新。

## 故障与投递

各来源独立保存CheckedAt、LastSuccess、NextAttempt、失败次数、详情缺失数和原因，失败按5/10/20/40/60分钟退避；429/503还尊重端点Retry-After。成功空集和故障区分；失败保留记录。三源均连续失败3次时，当天最多发一次明确的覆盖不完整提示，恢复后未发的故障提示不继续发送。

HTTP固定HTTPS来源，不跟随重定向、不带凭据；响应上限1MiB、协议包装白名单、JSON解析，不执行JS；NMC分页最多10页、上海项上限200，全国列表上限5000项。过量或部分失败标记不完整，已独立提交的正样本保留。HTTP缓存支持ETag/Last-Modified/304；304必须有原始缓存，陈旧HTTP Age/Date不能当作最新数据。上游数据自身的长期停更不可能仅靠HTTP成功完全判断。

观察、通知事件、消息任务与送达回执分别持久化。使用现有Heartbeat发送队列，送达成功后才ACK，重启不重发成功项；平台结果不确定时不盲目重放，status可见投递问题。新预警与升级不被另一源的空集或旧记录否决。

## 可评测入口

前台工具`assistant_weather_alerts`：`status`只读本地配置、来源健康、记录状态、最近30事件、pending/delivered/superseded计数和投递异常；`configure`需当前revision与Sir明确指令，可暂停/恢复及修改300–3600秒整分钟间隔。后台Agent不允许改配置。状态中的`observed_active`仅为最近观察，`not_reconfirmed`表示最近10分钟未重新确认，不能说已解除。`expired`与`explicitly_cancelled`区分。

服务器只读入口（以mybot账户运行并保留原环境）：

```text
REASONIX_HOME=/var/lib/mybot/reasonix REASONIX_ASSISTANT=1 /opt/mybot/current/reasonix assistant weather-alerts
```

`weather-alerts-check`是管理/验收入口，会读公网并更新所在Home的原生状态但不入通知队列；验收只在独立临时Home使用，不能拿它当纯只读状态查询。

## 已覆盖的自动测试

| 场景 | 期望 |
|---|---|
| 一个源先返回新预警，另一个请求被故意挂起 | 挂起解除之前已入队且可由消息通道送达 |
| 最新橙色与旧蓝色并存 | 橙色正常通知，旧蓝色不能覆盖 |
| 三源相同发布 | 单一事件、一次通知，补充已提供的截止时间 |
| 两源格式错误，一个源红色有效 | 红色照常入队，错误体不冒充空集 |
| 空列表/错误与既有预警并存 | 不自动解除 |
| 明确解除及落后源重现旧记录 | 解除可通知，旧记录不重启预警 |
| 正文中的“取消活动”/“未来将解除” | 不误当已解除 |
| 旧队列已被升级替换/明确过期 | 旧消息不能投递 |
| 作息外、暂停、revision改变、后台写配置 | 不取数/不提交/不越权 |
| 304与429 Retry-After | 有效缓存复用，持久化退避 |
| 重启/重复检查、投递结果不确定 | 成功不重发，不确定状态不盲目重放且可查 |
| 三源持续失败、随后恢复 | 一次事实性覆盖提示；恢复状态可见 |
| 中途重启及自定义起床时间 | 对齐下一调度格，不跳过；旧成功游标可安全沿用 |
| 实际Heartbeat原生调度 | 原生采集和消息发送不运行模型 |

完整相关包测试、竞态、lint/repolint结果见`weather-alert-build.json`与最终`weather-alert-cadence-build.json`，不放宽现有基线。真实二进制+独立临时数据库+真实官方GET验收由`scripts/alert-read-acceptance.py`完成；不生成真实微信测试消息、不使用真实模型或和风服务。

## 仍需实际观测的边界

本次真实读取时上海没有生效预警，因此上海真实新发布/升级/提前解除及真实微信收件尚未观察到，不能用合成夹具冒充。少量正样本字段只按官网网页协议校验；网页接口没有公开第三方调用配额或SLA，不能承诺永远可用、全覆盖、绝对不漏报或发布后恰好5分钟内到达。跨源发布时间/区域表述差异仍可能造成补充更新，轮询间发生后又消失且未留记录的短暂变化也可能缺失。低负载的5分钟检查是工程选择，错误退避会延后。

来源研究位于项目根`docs/research/FRIDAY_FREE_ALERT_SOURCES_VALIDATED_2026-10-26.md`。仅免费公开网页数据，原付费天气查询和晨报内容来源不变。
