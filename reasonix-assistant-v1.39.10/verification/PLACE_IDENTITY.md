# 地点身份与地区绑定

版本：`v1.39.10-assistant.17-place-identity`。

服务器地点表以 `place_id` 为键，每个地点独立保存 `name`、可选的 `region` 和经纬度。生产地区值由用户指定：`home` 为黄浦，`school` 为临港。经纬度继续沿用已有配置，不写入源码。

个人上下文和天气 `status` 返回的 `places` 从名称字符串表改为对象表。每个对象含 `place_id`、`name`、可选 `region`；`candidate` 的这三个字段由程序从同一个选定对象直接复制，再附加日期与星期。普通上下文不带经纬度，实际天气查询仍通过所选 ID 读取同一配置对象中的坐标，查询结果保留其地区。

共享上下文规则要求先确定地点 ID，再只使用该对象的名称与地区；不得跨地点拼接属性。未配置地区时保持未知。候选表示日程默认安排，不是实际定位，不能据此宣称 Sir 当前的位置或推断安全邮件中的异地登录。规则不包含针对具体地区的例句或词语替换。

验证包括：完整一周（含凌晨）的候选与地点记录一致；旧配置缺少地区时不继承其他地点的地区；显式选择另一个地点时其名称、地区和 API 坐标保持一致；助理模块及相关启动、心跳回归。隔离的真实模型验证检查地点区分、日期选择及模拟登录邮件；不发送微信消息、不读取生产邮件。模型验证仅代表测试样例，不能保证自由文本永不犯错。

部署为地点文件补充两个地区字段，备份原文件，并核验坐标、日程、邮箱配置、状态和凭据保持一致。部署状态与实际模型验证结果分别记录在 `place-identity-deployment.json`、`place-identity-model-probe.json`。
