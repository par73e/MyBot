# 微信最终答复输出

首次发布：`v1.39.10-assistant.9-final-only`。当前收尾修正版：`v1.39.10-assistant.10-output-closeout`。

收尾扩大检查发现 FinalOnly 尚未纳入运行时配置字段分类，repolint 也报告两处规模超限。修正版将该字段明确归类为适配器展示设置，并拆出微信配置定义与问答渲染函数，不扩大原基线；相关回归重新核验。

服务端用户配置：

```toml
[bot.weixin]
final_only = true
```

这是消息发送层的程序规则，不依赖模型遵守提示词。原有安装默认 false，保持兼容；本次部署仅将云端该字段设为 true，不改邮箱筛选或 Heartbeat 调度。

模型的 Message 事件只表示一次采样完成，不代表整个任务完成。渲染器暂存最新已提交正文；后续采样、失败重试、工具轮次会使旧正文失效。整轮 TurnDone 成功后才发送最终正文，不回退到文本增量或推理内容。重复结束事件不会重复发送。长答复继续按渠道长度上限分段。

工具执行状态、工具失败过程、重试、普通警告和上下文维护提示不发到微信；完整事件与会话记录仍由原控制器维护。需要用户作答／授权的事件正常发送。失败时只发简洁说明；取消时不发送旧答案。

测试覆盖多次工具调用与中间文字、失败／取消、采样丢弃、推理或未提交内容不泄露、必要交互、连续回合和长正文。真实 Agent 循环使用脚本模型与本地只读工具验证“工具正常运行、微信只得到最终答案”，不向真实微信发送测试消息。

邮箱行为说明：当前新增检查以 QQ IMAP UID／Gmail 历史游标识别新邮件，通知去重独立于已读状态；手动设为已读不会自动取消待分析邮件。Outlook 通过转发接入，只能看到 QQ 副本，不能同步原邮箱已读状态。本次不改变这些行为。
